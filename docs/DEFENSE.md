# Подготовка к опросу

## Что решает работа

Один полный цикл классификации: данные → классические признаки → модель →
обучение → оценка → интерпретация → перенос → стоимость. 39 вариантов меняют
датасет, архитектуру и исследовательский вопрос. Poetry — другая задача:
авторегрессионное предсказание следующего токена после дообучения GPT-2.

## Ключевые функции

| Функция | Что делает | Зачем нужна |
|---|---|---|
| registry.config | Параметры варианта | Связать код с карточкой и seed |
| data.prepare | Разбиение, class mapping, train mean/std | Избежать утечки val/test |
| data.Wrapped | Исходные индексы + transforms | Одни данные для CNN и классики |
| classical.feature | HOG/LBP/HSV/Hu/SIFT | Явные признаки вместо обучаемых |
| models.build | Создание архитектуры и головы | Менять модели под число классов |
| train.train | Forward, loss, backward, update, val, save | Реально обучать и возобновлять |
| train.mixed_batch | Mixup или CutMix + вес меток | Регуляризация только train |
| train.kd_loss | CE + KL с температурой и T² | Передать мягкие teacher-targets |
| evaluate.metrics | Accuracy/top3/F1/CM/ECE | Отдельно измерять ошибки и уверенность |
| evaluate.explanations | Grad-CAM, rollout или saliency | Проверять области, влияющие на ответ |
| experiments.transfer | Frozen probe → full FT | Отделить качество признаков от адаптации |
| report.build_reports | Таблицы и графики по логам | Не писать непроверяемые числа |
| poetry.Poems | Полные стихи → токеновые блоки | Causal language modelling |
| poetry.collator | Padding, labels=-100 на padding | Исключить pad из loss, сохранить EOS |

## Вопросы, на которых легко ошибиться

- **Почему fit scaler на val — утечка?** Он уже использует распределение
  отложенных данных; классификатор получает информацию вне train.
- **Почему probe требует eval для backbone?** requires_grad=False не выключает
  обновление running mean/variance BatchNorm в train-режиме.
- **Что сохраняется для resume?** Веса, optimizer momentum/moments, LR scheduler,
  AMP scaler, epoch, best score, RNG. Только model.state_dict недостаточно.
- **Почему 99% accuracy бывает плохим результатом?** При 99% одного класса
  модель может игнорировать остальные. Смотрим macro-F1 и per-class recall.
- **Почему T² в KD?** Температура уменьшает градиент мягкой KL-части;
  масштабирование компенсирует этот эффект в принятой формуле KD.
- **Прунинг всегда ускоряет?** Нет. Маски оставляют dense-операции; даже
  физическое удаление зависит от реализации и устройства. Нужны реальные замеры.
- **Чем Grad-CAM отличается от attention rollout?** Первый использует градиент
  логита по conv-картам, второй перемножает нормированные attention-матрицы
  слоёв ViT с residual-связями. Ни один не доказывает причинность.
- **Зачем cuda.synchronize?** CUDA запускает работу асинхронно; без синхронизации
  можно измерить время постановки задачи, а не инференса.
- **Что такое perplexity?** exp(средняя token-level cross-entropy). Сравнивать её
  корректно только при одинаковых токенизаторе, данных и протоколе.
- **Почему не загружать gpt2-fa-poetry вместо обучения?** Это готовая модель
  другого автора, её ответы не доказывают выполненный нами fine-tuning.
- **Как проверить улучшение poetry?** Одинаковые prompts/seed/decoding до и
  после, held-out loss/perplexity плюс ручная проверка связности и повторов.
